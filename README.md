# Netify (project folder/package still named NetPulse internally)

Android network speed & Wi-Fi info app. Display name and app icon are
"Netify" — the Gradle module names, package (`com.netpulse.android`), and
folder are still `NetPulse`/`netpulse` under the hood. Renaming those too is
just a find-and-replace across the project if you want full consistency
later; it doesn't affect how the app looks or behaves.

## Stack

- **Kotlin Multiplatform (KMP)** — one shared module (`shared/`) with all business
  logic: speed test engine, network info, history storage, models.
- **Compose Multiplatform** — one UI codebase rendered natively on both platforms
  via Skia, which is what gets you smooth 60fps on Android *and* iOS without
  writing the screens twice.
- **Ktor Client** — multiplatform HTTP client, used for the real download/upload/
  ping measurements (same technique as the HTML prototype, just native now).
- **GitHub Actions** — CI in `.github/workflows/build-android.yml` builds a debug
  APK on every push and uploads it as an artifact you can download from the
  Actions tab on your phone or laptop, no local Android Studio required for
  Android builds.

├── iosApp/                   # iOS Xcode wrapper (see note below)

## Important — read before building

**GitHub Actions can build the Android APK end-to-end** (it's just Gradle).
That part of "poori app GitHub se banao" works exactly as you want — push
code, Actions builds the APK, you download it on your phone.

**iOS is different.** Apple requires the actual `.xcodeproj`/`.xcworkspace`
to be generated by Xcode itself (its project file format isn't something you
hand-write reliably), and *running/signing* an iOS build needs a Mac —
either your own or a macOS runner on GitHub Actions (which exists and works,
but needs an Apple Developer account for real device installs, same as any
iOS app). So: Android — fully doable from your phone via GitHub. iOS —
needs a Mac (or GitHub's hosted macOS runner) at least once to generate and
sign the Xcode project. This is an Apple platform rule, not a limitation of
this codebase.

**Wi-Fi password reveal — platform reality check:**
- **Android**: possible only via root access, or via the QR-code export flow
  Android 10+ offers for networks *you* saved on *that* device. No app —
  ours included — can read another app or the OS's saved credentials
  without one of those two paths.
- **iOS**: there is **no path at all**, rooted or not. Apple's sandboxing
  has never exposed saved Wi-Fi passwords to any third-party app, App Store
  or not. This isn't a bug to fix later — plan the iOS version around
  showing SSID/signal/connection info only, with the password field simply
  not present on iOS.

Everything else (speed test, ping monitor, history, alerts, themes) works
identically and natively on both platforms.

## One-time setup before your first push

This scaffold doesn't include the `gradlew` wrapper script/jar (it's a
binary, best generated by tooling rather than hand-written). Before pushing
to GitHub, open the project once in Android Studio — it generates the
wrapper automatically on first sync — or run `gradle wrapper` from a
terminal if you have Gradle installed. The CI workflow
(`.github/workflows/build-android.yml`) calls `./gradlew`, so it needs that
file committed to the repo.

## Getting started

1. Open the `NetPulse/` folder in **Android Studio** (Hedgehog+) with the
   Kotlin Multiplatform plugin installed. It will offer to sync Gradle and
   fix any version numbers that have moved on since this was written.
2. Run `androidApp` on an emulator/device to see the shared UI on Android.
3. For iOS: open `iosApp/` in Xcode on a Mac once the wizard has generated
   it (Android Studio's KMP plugin can scaffold this for you via
   *File → New → Kotlin Multiplatform App* if you'd rather start from the
   official template and paste this shared/ code in).
4. Push to GitHub — `.github/workflows/build-android.yml` builds the Android
   APK automatically; grab it from the Actions tab → latest run → Artifacts.
